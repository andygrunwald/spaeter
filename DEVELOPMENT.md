# Development

## Setup

Requirements:

- Node.js (version in [`.node-version`](.node-version))
- `make`
- `git`
- `zip` (for packaging)
- Go and macOS, only to rebuild the [iPhone Shortcut](#iphone-shortcut)

```sh
make install   # npm ci, also downloads Chrome for Testing for the smoke test
make check     # lint, test, validate, smoke: run before every commit
```

Load the `extension` folder as an unpacked extension (`chrome://extensions` → Developer
mode → Load unpacked). After code changes, click the reload icon on the extension's card.
Logs from the background worker are under **service worker** on that card.

## Make targets

| Target          | What it does                                                            |
|-----------------|-------------------------------------------------------------------------|
| `make install`  | Install dev dependencies, including Chrome for Testing                  |
| `make lint`     | ESLint for JavaScript, markdownlint for all Markdown files              |
| `make test`     | Unit tests (`node --test`), including the iPhone Shortcut source checks |
| `make validate` | Static extension checks plus the vendored md5 drift check               |
| `make smoke`    | Loads the extension in headless Chrome and checks the UI in en and de   |
| `make check`    | All of the above                                                        |
| `make vendor`   | Copies blueimp-md5 from `node_modules` into `extension/vendor/`         |
| `make icons`    | Renders `extension/icons/*.png` from `assets/emoji_u1f42e.svg`          |
| `make zip`      | Packages the extension as `dist/spaeter.zip`                            |
| `make shortcuts` | Builds and signs `ios/Später.shortcut` (macOS only), see [iPhone Shortcut](#iphone-shortcut) |
| `make shortcuts-compile` | Compiles the iPhone Shortcut unsigned into `build/` (any OS) |

`make smoke` saves screenshots when `SCREENSHOTS` points to a directory:
`mkdir -p /tmp/shots && SCREENSHOTS=/tmp/shots make smoke`.

## Architecture

```text
extension/
  manifest.json          MV3 manifest; strings come from _locales
  _locales/{en,de}/      UI strings (chrome.i18n)
  background.js          service worker: popup on/off, one-click add, badge + notification
  popup.{html,js}        confirmation popup (type, title, preview, add)
  options.{html,js}      settings: RTM connection, list, behavior, templates
  style.css              shared styles for popup and options, light and dark
  lib/
    rules.js             domains per type and the de/en presets: the single source of truth
    classify.js          classify(url), formatTitle(template, title)
    metadata.js          title lookup: oEmbed, then og:title/document.title, then tab.title
    rtm.js               RTM API client: signing, auth flow, lists, addTask
    addLink.js           prepareLink(tab) and addLink(link, settings), used by popup and background
    settings.js          chrome.storage.local with defaults
    i18n.js              t(key) and localize() for data-i18n attributes
  vendor/md5.js          generated by `make vendor`, do not edit
ios/
  spaeter.cherri         iPhone Shortcut entry point (Cherri source)
  setup.cherri           setup: RTM login, list and language, writes spaeter.json
  share.cherri           Share Sheet: classify, look up the title, add the task
  title.cherri           title lookup: oEmbed, Safari Reader, page <title>, URL
  generated/             includes generated from extension/lib/rules.js (git-ignored)
  Später.shortcut        signed Shortcut built by `make shortcuts`, do not edit
  shortcuts.lock         hash of the inputs the signed Shortcut was built from
scripts/                 vendor, icons, validation, smoke test and Shortcut build scripts
tests/                   node:test unit tests and the iPhone Shortcut source checks
```

Plain ES modules, no bundler and no build step: the `extension` folder is loaded as is.

### Google Chrome Extension: Data flow

1. The toolbar button is clicked. With the confirmation popup on, `popup.html` opens;
   otherwise `background.js` receives `action.onClicked`. `background.js` switches between
   the two with `chrome.action.setPopup` whenever the setting changes.
2. `prepareLink(tab)` classifies the URL by host (`rules.js`) and looks up the title.
   `activeTab` grants access to the current page only after the click.
3. `addLink()` formats the task name from the type's template and calls `addTask()`.
4. `addTask()` runs four signed RTM calls: `rtm.timelines.create`, `rtm.tasks.add`,
   `rtm.tasks.setURL`, `rtm.tasks.addTags`.

### RTM API notes

- Every request is signed: `api_sig = md5(secret + key1 + value1 + …)` with keys sorted.
  Web Crypto has no MD5, hence the vendored blueimp-md5.
- Authentication uses RTM's desktop flow (`rtm.auth.getFrob` → user approves in a tab →
  `rtm.auth.getToken`), which needs no callback URL. The token is stored in
  `chrome.storage.local` with the key and secret.
- **Smart Add (`parse=1`) is not used on purpose.** It has no escaping, so titles with
  `#`, `!1`, `^`, `//`, `*` or `@` would become lists, tags, priorities or notes.
- RTM's JSON returns single elements as objects and multiple as arrays; `rtm.js`
  normalizes with `[x].flat()`.
- Rate limit: about one request per second, bursts of three. RTM delays rather than
  rejects, so the four calls per task are fine.
- Docs: <https://www.rememberthemilk.com/services/api/>

## CI

The iPhone Shortcut can't run in CI, and signing it needs macOS. CI compiles it unsigned
(`make shortcuts-compile`), and `tests/shortcuts.test.js` checks its sources against the
extension code and that the committed signed file was rebuilt (see
[iPhone Shortcut](#iphone-shortcut)).

## iPhone Shortcut

The iPhone Shortcut `ios/Später.shortcut` is compiled from [Cherri](https://cherrilang.org)
sources in `ios/`. Cherri is a language that compiles to Apple Shortcuts. Never edit or
export the `.shortcut` file by hand; change the sources and rebuild it.

### Requirements

- **A Mac.** Only macOS can sign Shortcuts (`shortcuts sign`), and iOS refuses to import
  unsigned ones.
- Go, to build the pinned Cherri compiler (`CHERRI_VERSION` in the `Makefile`).
- Network access: the Cherri source is downloaded on the first build, and signing contacts
  Apple.

### How it works

- `ios/spaeter.cherri` is the entry point. It reads `iCloud Drive/Shortcuts/spaeter.json`
  and picks a mode: with Share Sheet input it adds the link; started directly it shows a
  menu (add link from clipboard, change list and language, set up); without a config it
  runs the setup.
- `ios/setup.cherri` runs RTM's desktop auth flow (getFrob → approval in Safari →
  getToken), lets the user choose list and language, and writes `spaeter.json`. It only
  runs when the Shortcut is started directly: switching to Safari ends a Shortcut that
  runs inside another app's Share Sheet.
- `ios/share.cherri` checks that the setup ran, classifies the link, looks up its title
  and makes the four signed RTM calls, like `addTask()` in `extension/lib/rtm.js`.
- `ios/title.cherri` looks up the title: oEmbed for YouTube, Vimeo and Spotify, then
  Safari Reader, then the page's `<title>`, and the URL as a last resort.
- Two Shortcuts behaviours to keep in mind: an empty text counts as "has any value", so
  emptiness is checked with Match Text; and "Get Text" on a downloaded web page returns the
  rendered text, so the download is renamed to `.txt` to read its source.
- `ios/generated/classify.cherri` and `ios/generated/presets.cherri` are generated from
  `extension/lib/rules.js` by `scripts/build-shortcut-rules.mjs`, so both clients classify
  links and name tasks the same way.
- RTM returns one task series as an object and several as a list, and Shortcuts treats
  dictionaries and lists differently. The task IDs are therefore read from the raw JSON
  with a regex.

### Rebuild

1. Change `ios/*.cherri`, `extension/lib/rules.js` or the generator.
2. Run `make shortcuts`. It builds Cherri into `.cache/` on the first run, generates the
   includes, compiles with `--skip-sign`, signs with
   `shortcuts sign --mode anyone`, and updates `ios/shortcuts.lock`.
3. Test it: AirDrop `ios/Später.shortcut` to an iPhone (or open it on the Mac), run the
   setup and share a link.
4. Commit `ios/Später.shortcut` and `ios/shortcuts.lock` together with your change.

Cherri always runs with `--skip-sign`: if macOS signing fails, it would otherwise upload
the Shortcut to a third-party signing service. `make shortcuts-compile` compiles without
signing on any OS; CI runs it to catch errors in the sources.

### Testing on a Mac

Shortcuts also runs on macOS, so logic can be checked without an iPhone. Compile a small
wrapper Shortcut that includes the file under test (for example `ios/title.cherri`) and
ends with `output(…)`, sign it, import it once, and run it from the terminal:

```sh
shortcuts run "<name>" --input-path url.txt --output-path out --output-type public.plain-text
```

### Checks

`tests/shortcuts.test.js` derives every signature string from `extension/lib/rtm.js` and
requires it in the sources, checks the generated includes against `rules.js`, and fails
when `ios/shortcuts.lock` no longer matches the inputs, i.e. when the signed Shortcut
wasn't rebuilt after a change.

## Adding a domain

1. Add the domain to `DOMAINS` in [`extension/lib/rules.js`](extension/lib/rules.js). A
   domain matches all of its subdomains.
2. Add a case to `tests/classify.test.js`.
3. If the site has an oEmbed endpoint, add it to `OEMBED` in `extension/lib/metadata.js`,
   to `host_permissions` in `manifest.json`, and to the title lookup in `ios/share.cherri`.
4. Update the table in [`docs/link-classification.md`](docs/link-classification.md).
5. Rebuild the iPhone Shortcut on a Mac with `make shortcuts` and commit it.
6. Run `make check`.

## Adding a language

UI language:

1. Copy `extension/_locales/en/messages.json` to `extension/_locales/<lang>/messages.json`
   (a [Chrome locale code](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales))
   and translate every `message`. Keep keys and placeholders unchanged.
2. Run `make validate` (keys and placeholders must match the default locale) and
   `make smoke`. To include the new language in the smoke test, add it to `LANGUAGES` in
   `scripts/smoke.mjs`.

Task name preset (optional, independent of the UI language):

1. Add a preset to `PRESETS` in `extension/lib/rules.js`.
2. Add an `<option>` to the preset select in `extension/options.html` and a message key for
   its label to every locale.
3. Add a menu label for the preset to `PRESET_LABELS` in
   `scripts/build-shortcut-rules.mjs` and rebuild the iPhone Shortcut with `make shortcuts`.
4. Run `make check`.

New UI strings always go into **every** locale; `make validate` fails otherwise. Use
`data-i18n="key"` in HTML and `t('key')` in JavaScript.

## Dependencies and Renovate

[Renovate](renovate.json) opens update PRs weekly, only for releases that are at least
14 days old. Nothing merges automatically: every update PR needs a review.

`blueimp-md5` is vendored into the extension: on its update PR, run `make vendor` and
commit `extension/vendor/md5.js`. CI fails until the vendored copy matches.

Renovate also updates `CHERRI_VERSION` in the `Makefile`: on that PR, rebuild the iPhone
Shortcut with `make shortcuts` on a Mac and commit it. CI fails until the lock matches.

## Icons

The icon is the cow face emoji (U+1F42E) from Google's Noto Emoji (Apache-2.0). Don't use
Remember The Milk's cow logo: their branding guidelines forbid it. To change the icon,
replace `assets/emoji_u1f42e.svg`, update the script and the license note in
`extension/icons/LICENSE`, and run `make icons`.

## Packaging

`make zip` creates `dist/spaeter.zip` with the contents of `extension/`. CI uploads the
same folder as the `spaeter-extension` artifact. Bump `version` in
`extension/manifest.json` and `package.json` together.
