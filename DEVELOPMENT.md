# Development

## Setup

Requirements: Node.js (version in [`.node-version`](.node-version)), `make`, `git`, and
`zip` for packaging.

```sh
make install   # npm ci, also downloads Chrome for Testing for the smoke test
make check     # lint, test, validate, smoke: run before every commit
```

Load the `extension` folder as an unpacked extension (`chrome://extensions` → Developer
mode → Load unpacked). After code changes, click the reload icon on the extension's card.
Logs from the background worker are under **service worker** on that card.

## Make targets

| Target          | What it does                                                            |
|-----------------|-------------------------------------------------------------------------|
| `make install`  | Install dev dependencies, including Chrome for Testing                  |
| `make lint`     | ESLint for JavaScript, markdownlint for all Markdown files              |
| `make test`     | Unit tests (`node --test`) and the iOS guide consistency tests          |
| `make validate` | Static extension checks plus the vendored md5 drift check               |
| `make smoke`    | Loads the extension in headless Chrome and checks the UI in en and de   |
| `make check`    | All of the above                                                        |
| `make vendor`   | Copies blueimp-md5 from `node_modules` into `extension/vendor/`         |
| `make icons`    | Renders `extension/icons/*.png` from `assets/emoji_u1f42e.svg`          |
| `make zip`      | Packages the extension as `dist/spaeter.zip`                            |

`make smoke` saves screenshots when `SCREENSHOTS` points to a directory:
`mkdir -p /tmp/shots && SCREENSHOTS=/tmp/shots make smoke`.

## Architecture

```text
extension/
  manifest.json          MV3 manifest; strings come from _locales
  _locales/{en,de}/      UI strings (chrome.i18n)
  background.js          service worker: popup on/off, one-click add, badge + notification
  popup.{html,js}        confirmation popup (type, title, preview, add)
  options.{html,js}      settings: RTM connection, list, behavior, templates, iPhone values
  style.css              shared styles for popup and options, light and dark
  lib/
    rules.js             domains per type and the de/en presets: the single source of truth
    classify.js          classify(url), formatTitle(template, title)
    metadata.js          title lookup: oEmbed, then og:title/document.title, then tab.title
    rtm.js               RTM API client: signing, auth flow, lists, addTask
    addLink.js           prepareLink(tab) and addLink(link, settings), used by popup and background
    settings.js          chrome.storage.local with defaults
    i18n.js              t(key) and localize() for data-i18n attributes
  vendor/md5.js          generated by `make vendor`, do not edit
ios/SHORTCUT.md          guide for the iPhone Shortcut
scripts/                 vendor, icons, validation and smoke test scripts
tests/                   node:test unit tests and the iOS guide consistency tests
```

Plain ES modules, no bundler and no build step: the `extension` folder is loaded as is.

### Data flow

1. The toolbar button is clicked. With the confirmation popup on, `popup.html` opens;
   otherwise `background.js` receives `action.onClicked`. `background.js` switches between
   the two with `chrome.action.setPopup` whenever the setting changes.
2. `prepareLink(tab)` classifies the URL by host (`rules.js`) and looks up the title.
   `activeTab` grants access to the current page only after the click.
3. `addLink()` formats the task name from the type's template and calls `addTask()`.
4. `addTask()` runs four signed RTM calls: `rtm.timelines.create`, `rtm.tasks.add`,
   `rtm.tasks.setURL`, `rtm.tasks.addTags`.

### RTM API notes

- Every request is signed: `api_sig = md5(secret + key1 + value1 + …)` with keys sorted.
  Web Crypto has no MD5, hence the vendored blueimp-md5.
- Authentication uses RTM's desktop flow (`rtm.auth.getFrob` → user approves in a tab →
  `rtm.auth.getToken`), which needs no callback URL. The token is stored in
  `chrome.storage.local` with the key and secret.
- **Smart Add (`parse=1`) is not used on purpose.** It has no escaping, so titles with
  `#`, `!1`, `^`, `//`, `*` or `@` would become lists, tags, priorities or notes.
- RTM's JSON returns single elements as objects and multiple as arrays; `rtm.js`
  normalizes with `[x].flat()`.
- Rate limit: about one request per second, bursts of three. RTM delays rather than
  rejects, so the four calls per task are fine.
- Docs: <https://www.rememberthemilk.com/services/api/>

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on pushes to `main` and on
pull requests:

| Job                  | Checks                                                                       |
|----------------------|------------------------------------------------------------------------------|
| `lint`               | `npm run lint`                                                               |
| `test`               | `npm test`, including `tests/ios-guide.test.js`                              |
| `validate-extension` | `npm run validate`, vendored md5 is current, uploads `extension/` as artifact |
| `smoke`              | `npm run smoke` in headless Chrome, uploads screenshots                      |
| `docs`               | Link check of all Markdown files (lychee)                                    |
| `renovate-config`    | `renovate-config-validator --strict`                                         |

The iPhone Shortcut can't run in CI. Instead, `tests/ios-guide.test.js` reads
`ios/SHORTCUT.md` and checks that its host regexes, templates and tags, per-call
signature strings and worked example match what the extension code produces.

## Adding a domain

1. Add the domain to `DOMAINS` in [`extension/lib/rules.js`](extension/lib/rules.js). A
   domain matches all of its subdomains.
2. Add a case to `tests/classify.test.js`.
3. If the site has an oEmbed endpoint, add it to `OEMBED` in `extension/lib/metadata.js`,
   to `host_permissions` in `manifest.json`, and to the oEmbed table in `ios/SHORTCUT.md`.
4. Update the regex for the type in `ios/SHORTCUT.md` (Type detection table). `make test`
   tells you the exact expected regex if it doesn't match.
5. Update the "How links are classified" table in the README.
6. Run `make check`.

## Adding a language

UI language:

1. Copy `extension/_locales/en/messages.json` to `extension/_locales/<lang>/messages.json`
   (a [Chrome locale code](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales))
   and translate every `message`. Keep keys and placeholders unchanged.
2. Run `make validate` (keys and placeholders must match the default locale) and
   `make smoke`. To include the new language in the smoke test, add it to `LANGUAGES` in
   `scripts/smoke.mjs`.

Task name preset (optional, independent of the UI language):

1. Add a preset to `PRESETS` in `extension/lib/rules.js`.
2. Add an `<option>` to the preset select in `extension/options.html` and a message key for
   its label to every locale.
3. Add columns for the preset to the template table in `ios/SHORTCUT.md` and extend
   `tests/ios-guide.test.js`.
4. Run `make check`.

New UI strings always go into **every** locale; `make validate` fails otherwise. Use
`data-i18n="key"` in HTML and `t('key')` in JavaScript.

## Dependencies and Renovate

[Renovate](renovate.json) opens update PRs weekly, only for releases that are at least
14 days old. Nothing merges automatically: every update PR needs a review.

`blueimp-md5` is vendored into the extension: on its update PR, run `make vendor` and
commit `extension/vendor/md5.js`. CI fails until the vendored copy matches.

## Icons

The icon is the cow face emoji (U+1F42E) from Google's Noto Emoji (Apache-2.0). Don't use
Remember The Milk's cow logo: their branding guidelines forbid it. To change the icon,
replace `assets/emoji_u1f42e.svg`, update the script and the license note in
`extension/icons/LICENSE`, and run `make icons`.

## Packaging

`make zip` creates `dist/spaeter.zip` with the contents of `extension/`. CI uploads the
same folder as the `spaeter-extension` artifact. Bump `version` in
`extension/manifest.json` and `package.json` together.

## Secrets

Never commit RTM API keys, shared secrets, auth tokens or frobs: see
[AGENTS.md](AGENTS.md). Tests use RTM's documented example secret `BANANAS` and
placeholders such as `YOUR_API_KEY`.
